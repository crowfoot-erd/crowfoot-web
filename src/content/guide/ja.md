CrowfootはWeb上でERDを描き、データベースとやり取りし、チームで一緒に使うツールです。このガイドは、最初のドキュメントを作るところから、標準を決めてデータベースに反映するところまでを作業の順に説明します。

![ERDエディタの画面](/landing/editor-ja-light.webp)

以下のスクリーンショットは韓国語の画面です。本文のメニュー名は日本語の表記です。

## 1. はじめに

1. GitHubまたはGoogleアカウントでログインします。
2. **ワークスペース**を作ります。ワークスペースは、ドキュメント、データベース接続、用語辞書、ドメインタイプをまとめて入れる単位です。チームやプロジェクトごとに1つ作ることをおすすめします。
3. ワークスペースの**ERD**タブでドキュメントを作ります。方法は4つあります。

| 方法 | 使う場面 |
| --- | --- |
| 新規ERDドキュメント | 空のキャンバスから描くとき |
| SQLを取り込む | すでに`CREATE TABLE`文があるとき |
| DBから取り込む | 既存のデータベースの構造をそのまま読み込むとき |
| テンプレートから始める | 似たテーマの例から始めるとき |

ドキュメントを作るときに**対象DBMS**(MySQL、PostgreSQLなど)を選びます。作成後は変更できません。別のDBMS用が必要なら、**ツール › 別のDBMSに複製**で新しいドキュメントを作ります。

## 2. ERDを描く

### テーブルとカラム

- 空いている場所を**右クリック › 新規エンティティ**でテーブルを作ります。
- テーブル下部の**カラムを追加**でカラムを入れます。名前、型、長さ、NN(NOT NULL)はテーブル上で直接変更します。
- 鍵のアイコンを押すと主キーになります。
- カラム名を**ダブルクリックするとカラム情報**が開きます。論理名、デフォルト値、ドメインタイプ、説明はここで決めます。
- カラムには**物理名**(データベースに作られる名前)と**論理名**(人が読む名前)があります。**表示**メニューでどちらを見せるかを選びます。

### リレーション

- テーブルの縁の点を押し、種類(1:N、1:1)と区分(依存、非依存)を選んでから相手のテーブルを押します。外部キーカラムは自動で作られます。
- リレーション線を**右クリック › リレーションを編集**すると、カーディナリティや削除・更新時の動作を変えられます。
- 同じダイアログの**カラムマッピング**で、外部キーに使う子側のカラムを変えられます。既存のカラムを外部キーにしたいとき、リレーションを削除して作り直す必要はありません。

![リレーション編集ダイアログのカラムマッピング](/guide-assets/relationship-mapping.webp)

### 整える

- **自動レイアウト**はテーブルをリレーションに沿って並べます。横の矢印から配置モード(階層型、ハブ中心、ハイブリッド)と向き(上から下へ、左から右へ)を選びます。
- 複数のテーブルを選んで**右クリック › 新規グループ**でまとめると色で区別され、そのグループだけを表示できます。
- **メモ**は空いている場所を右クリックして作ります。テーブルの上にドロップすると、そのテーブルに付きます。

![配置の向きを選ぶ](/guide-assets/layout-direction.webp)

### コピーと貼り付け

- テーブルやメモを**右クリック › コピー / 複製**します。ショートカットは`Ctrl/Cmd+C`、`V`、`D`です。
- コピーしたものは、同じブラウザの**別のタブで開いた別のドキュメント**にも貼り付けられます。一緒に選んだテーブル間のリレーションも付いてきます。
- 間違いは`Ctrl/Cmd+Z`で戻します。自動レイアウトや貼り付けのように一度に多くが変わる操作も、1回で戻ります。
- すべてのショートカットは`Ctrl/Cmd+/`で確認できます。

## 3. 標準を作る — 単語、用語、ドメインタイプ

複数の人が複数のドキュメントを描くと、同じものを違う名前で呼び、違う形で保存するようになります。`email`がある場所では`VARCHAR(100)`、別の場所では`VARCHAR(255)`になります。これを防ぐため、Crowfootはワークスペースごとに3種類の標準を持ちます。

| 標準 | 答える問い | 例 |
| --- | --- | --- |
| **単語** | この名前の部分は何を意味するか | `user` → 会員 |
| **用語** | このカラムは何で、どの型か | `user_email` → 会員メール、ドメインタイプ「メール」 |
| **ドメインタイプ** | この種類の値はどう保存するか | メール = `VARCHAR(191)`、NOT NULL |

3つともツールバーの**用語辞書**パネルで管理します。**ワークスペース**タブに単語と用語が、**ドメインタイプ**タブにドメインタイプがあります。ワークスペースのすべてのドキュメントが同じ標準を使います。

![用語辞書パネルのドメインタイプタブ](/guide-assets/standard-panel.webp)

### おすすめの順序

1. **まずドメインタイプを作ります。** メール、金額、作成日時のように、複数のテーブルに繰り返し出てくる値の種類を決めます。
2. **単語を登録します。** `user` → 会員、`order` → 注文のように、名前に使う部分とその意味です。型は書きません。
3. **用語を登録します。** `user_email`のようにカラム名全体を書き、ドメインタイプを選びます。ドメインタイプを選んだ項目が用語です。

すでに型表記を書いた辞書項目があれば、編集ダイアログの**ドメインタイプにする**でその表記をドメインタイプに移せます。

### カラムを作るとき

カラム名を入力し始めると、辞書が候補を表示します。

![カラム名の候補](/guide-assets/term-suggest.webp)

- **用語**を選ぶと、名前全体と論理名が入り、ドメインタイプが連携されたまま型・長さ・NULL許可・デフォルト値が入ります。
- **単語**を選ぶと、入力中の部分だけが補完されます。`user_em`で`email`を選ぶと`user_email`になります。続けて入力できます。
- リスト最上部の**論理名**は、入力した名前がどの論理名になるかをあらかじめ示します。

ドメインタイプを使うカラムには、名前の横に`D`バッジが付きます。

### 標準と異なる値にしたいとき

カラムはドメインタイプを保ったまま、異なる値を持てます。カラム情報で長さを変えると、何が異なるかを知らせ、バッジは`D*`になります。**ドメインタイプの値に戻す**で一度に合わせられます。

カラム名が辞書の用語と同じなのにドメインタイプが違う場合、カラム情報は**辞書の標準**を示し、**適用**をすすめます。

![カラム情報のドメインタイプ](/guide-assets/domain-column.webp)

### 標準を変えるとき

ドメインタイプを変更すると、それを使うカラムに反映するかを確認します。カラムごとに変わる値をプレビューし、反映するカラムを選びます。異なる値にすると決めた属性はスキップします。

![ドメインタイプ変更の反映プレビュー](/guide-assets/domain-propagation.webp)

- 今開いていないドキュメントはすぐには変わりません。次にそのドキュメントを開いた編集者に、ドメインタイプが変更されたという通知が表示されます。
- 反映は元に戻す1回で取り消せます。

### 既存のドキュメントに論理名を入れる

データベースから取り込んだドキュメントは、論理名が空のことがよくあります。**ツール › 論理名推論**は、辞書の単語と用語を使って`user_id`を「会員ID」のように埋めます。適用する前に結果をプレビューして選びます。

## 4. データベースとのやり取り

ワークスペースの**データベース**タブで接続を登録します。開発用のデータベースがなければ、無料のデータベースを発行できます。

| したいこと | 方法 |
| --- | --- |
| データベースの構造をドキュメントに | データベースタブの**DBから取り込む** |
| ドキュメントをSQLに | エディタの**SQL生成** |
| ドキュメントをデータベースに作る | SQL生成ダイアログの**デプロイ** |
| ドキュメントを直したあとデータベースを合わせる | **マイグレーションDDL** — 変わった部分だけのSQL |
| データベースの変更をドキュメントに取り込む | **ツール › DB同期** |
| 手で作ったドキュメントをデータベースに連携 | **ツール › データベース接続** |

データベースに反映した変更は元に戻せません。実行前に表示されるSQLを必ず確認してください。

## 5. データを見る

連携したデータベースのデータをそのまま見て編集できます。データベースタブの**データを見る**、エディタの**ツール › データを見る**、テーブルを**右クリック › このテーブルのデータを見る**から開きます。

![データブラウザ](/guide-assets/data-tab.webp)

- **データ**タブ: 見出しを押して並べ替え、条件で絞り込み、CSVでダウンロードします。
- **行の編集**: セルをダブルクリックして編集します。編集内容は下に集まり、**適用**を押すとまとめて反映されます。1件でも失敗するとすべて取り消されます。
- **SQL**タブ: 文を直接実行します。`Ctrl/Cmd+Enter`でカーソルのある文だけを実行します。データを変える文は確認を経ます。

![行の編集](/guide-assets/row-edit.webp)

データを見る機能はEditor以上が使えます。

## 6. 一緒に使う

### メンバーとロール

ワークスペースの**メンバー**タブで人やチームを招待します。

| ロール | できること |
| --- | --- |
| Viewer | 閲覧 |
| Commenter | 閲覧、コメント |
| Editor | ドキュメントの編集、データベース接続、辞書とドメインタイプの管理、データを見る |
| Owner | 上記すべて、メンバー管理、ドキュメントとワークスペースの削除 |

### 同時に編集する

同じドキュメントを複数の人が開くと、互いのカーソルと変更がリアルタイムで見えます。誰かが編集ダイアログを開いているテーブルは、他の人にはロックされたものとして表示されます。

### 外に見せる

- **共有**は、ログインなしで見られる読み取り専用リンクを作ります。期間を決められ、いつでも取り消せます。
- **書き出し**は、画像とドキュメントファイル(`.crown`)を作ります。

### バージョン履歴

保存するたびにバージョンが残ります。**ツール › バージョン履歴**で以前のバージョンを見て、2つのバージョンを比べ、元に戻せます。

## 7. 点検する

ツールバーの**検証**はドキュメントを検査します。主キーのないテーブル、型が合わない外部キー、命名規則に合わない名前、論理名のないカラムなどを見つけます。項目を押すと該当するテーブルに移動します。

## 8. よくある質問

**用語辞書とドメインタイプは何が違いますか？**
辞書は名前の標準で、ドメインタイプは型の標準です。`user_email`、`backup_email`、`contact_mail`は名前が違うので辞書項目はそれぞれ別ですが、ドメインタイプは3つとも「メール」1つを使います。

**単語と用語は別々に登録しますか？**
同じリストに登録します。ドメインタイプを選んだ項目(または型表記を書いた項目)が用語で、残りが単語です。

**ドメインタイプを削除するとカラムはどうなりますか？**
カラムの値はそのままです。リンクだけが切れたものとして表示されます。

**別のワークスペースに貼り付けるとドメインタイプはどうなりますか？**
ドメインタイプはワークスペースに属します。別のワークスペースのドキュメントではリンクが切れたものとして表示され、値はそのままです。

**保存はいつされますか？**
編集を止めると自動で保存されます。`Ctrl/Cmd+S`や**保存**ボタンですぐに保存することもできます。
