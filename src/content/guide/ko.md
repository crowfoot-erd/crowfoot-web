Crowfoot는 웹에서 ERD를 그리고, 데이터베이스와 주고받고, 팀이 함께 쓰는 도구입니다. 이 가이드는 처음 문서를 만드는 일부터 표준을 세우고 데이터베이스에 반영하는 일까지를 작업 순서대로 설명합니다.

![ERD 에디터 화면](/landing/editor-ko-light.webp)

## 1. 시작하기

1. GitHub 또는 Google 계정으로 로그인합니다.
2. **워크스페이스**를 만듭니다. 워크스페이스는 문서, 데이터베이스 연결, 용어 사전, 도메인 타입을 함께 담는 단위입니다. 팀이나 프로젝트마다 하나씩 만드는 것을 권합니다.
3. 워크스페이스의 **ERD** 탭에서 문서를 만듭니다. 방법은 넷입니다.

| 방법 | 언제 쓰나 |
| --- | --- |
| 새 ERD 문서 | 빈 캔버스에서 직접 그릴 때 |
| SQL 가져오기 | `CREATE TABLE` 문이 이미 있을 때 |
| DB에서 가져오기 | 이미 있는 데이터베이스의 구조를 그대로 읽어 올 때 |
| 템플릿으로 시작 | 비슷한 주제의 예시에서 시작할 때 |

문서를 만들 때 **대상 DBMS**(MySQL, PostgreSQL 등)를 고릅니다. 만든 뒤에는 바꿀 수 없습니다. 다른 DBMS용이 필요하면 **도구 › 다른 DBMS로 복제**로 새 문서를 만듭니다.

## 2. ERD 그리기

### 테이블과 컬럼

- 빈 곳을 **우클릭 › 엔터티 생성**으로 테이블을 만듭니다.
- 테이블 아래의 **컬럼 추가**로 컬럼을 넣습니다. 이름, 타입, 길이, NN(NOT NULL)은 테이블 위에서 바로 고칩니다.
- 열쇠 아이콘을 누르면 기본 키가 됩니다.
- 컬럼 이름을 **두 번 누르면 컬럼 정보** 창이 열립니다. 논리명, 기본값, 도메인 타입, 설명은 여기서 정합니다.
- 컬럼에는 **물리명**(데이터베이스에 만들어지는 이름)과 **논리명**(사람이 읽는 이름)이 있습니다. **보기** 메뉴에서 어느 쪽을 보일지 고릅니다.

### 관계

- 테이블 가장자리의 점을 누르고 유형(1:N, 1:1)과 종류(식별, 비식별)를 고른 뒤 상대 테이블을 누릅니다. 외래 키 컬럼은 자동으로 만들어집니다.
- 관계선을 **우클릭 › 관계 편집**하면 기수, 삭제·수정 시 동작을 바꿉니다.
- 같은 창의 **컬럼 매핑**에서 외래 키로 쓸 자식 쪽 컬럼을 바꿀 수 있습니다. 이미 있는 컬럼을 외래 키로 쓰고 싶을 때 관계를 지우고 다시 만들 필요가 없습니다.

![관계 편집 창의 컬럼 매핑](/guide-assets/relationship-mapping.webp)

### 정리하기

- **자동 배치**는 테이블을 관계에 따라 정렬합니다. 옆의 화살표에서 배치 모드(계층형, 허브 중심, 하이브리드)와 방향(위에서 아래로, 왼쪽에서 오른쪽으로)을 고릅니다.
- 테이블을 여러 개 골라 **우클릭 › 그룹 생성**으로 묶으면 색으로 구분되고, 그 그룹만 따로 볼 수 있습니다.
- **메모**는 빈 곳을 우클릭해 만듭니다. 테이블 위로 끌어 놓으면 그 테이블에 붙습니다.

![배치 방향 고르기](/guide-assets/layout-direction.webp)

### 복사와 붙여넣기

- 테이블이나 메모를 **우클릭 › 복사 / 복제**합니다. 단축키는 `Ctrl/Cmd+C`, `V`, `D`입니다.
- 복사한 것은 같은 브라우저의 **다른 탭에서 연 다른 문서**에도 붙여 넣을 수 있습니다. 함께 고른 테이블 사이의 관계도 따라옵니다.
- 실수는 `Ctrl/Cmd+Z`로 되돌립니다. 자동 배치나 붙여넣기처럼 한 번에 많은 것이 바뀌는 작업도 한 번에 되돌아갑니다.
- 전체 단축키는 `Ctrl/Cmd+/`로 봅니다.

## 3. 표준 만들기 — 단어, 용어, 도메인 타입

여러 사람이 여러 문서를 그리면 같은 것을 다르게 부르고 다르게 저장하게 됩니다. `email`이 어디서는 `VARCHAR(100)`, 어디서는 `VARCHAR(255)`가 됩니다. Crowfoot는 이를 막기 위해 워크스페이스마다 세 가지 표준을 둡니다.

| 표준 | 답하는 질문 | 예 |
| --- | --- | --- |
| **단어** | 이 이름 조각은 무슨 뜻인가 | `user` → 회원 |
| **용어** | 이 컬럼은 무엇이고 어떤 타입인가 | `user_email` → 회원 이메일, 도메인 타입 "이메일" |
| **도메인 타입** | 이 종류의 값은 어떻게 저장하나 | 이메일 = `VARCHAR(191)`, NOT NULL |

셋 다 도구 모음의 **용어 사전** 패널에서 관리합니다. **워크스페이스 사전** 탭에 단어와 용어가, **도메인 타입** 탭에 도메인 타입이 있습니다. 워크스페이스의 모든 문서가 같은 표준을 씁니다.

![용어 사전 패널의 도메인 타입 탭](/guide-assets/standard-panel.webp)

### 권하는 순서

1. **도메인 타입부터 만듭니다.** 이메일, 금액, 생성 일시처럼 여러 테이블에 반복해서 나오는 값의 종류를 정합니다.
2. **단어를 등록합니다.** `user` → 회원, `order` → 주문처럼 이름에 쓰는 조각과 그 뜻입니다. 타입은 적지 않습니다.
3. **용어를 등록합니다.** `user_email`처럼 컬럼 이름 전체를 적고 도메인 타입을 고릅니다. 도메인 타입을 고른 항목이 용어입니다.

이미 타입 표기를 적어 둔 사전 항목이 있다면, 수정 창의 **도메인 타입으로 만들기**로 그 표기를 도메인 타입으로 옮길 수 있습니다.

### 컬럼을 만들 때

컬럼 이름을 치기 시작하면 사전이 제안을 보여 줍니다.

![컬럼 이름 제안](/guide-assets/term-suggest.webp)

- **용어**를 고르면 이름 전체와 논리명이 채워지고, 도메인 타입이 연결된 채로 타입·길이·NULL 허용·기본값이 들어갑니다.
- **단어**를 고르면 지금 치고 있는 조각만 완성됩니다. `user_em`에서 `email`을 고르면 `user_email`이 됩니다. 계속 이어서 칠 수 있습니다.
- 목록 맨 위의 **논리명**은 지금 친 이름이 어떤 논리명이 될지 미리 보여 줍니다.

도메인 타입을 쓰는 컬럼에는 이름 옆에 `D` 배지가 붙습니다.

### 표준과 다르게 써야 할 때

컬럼은 도메인 타입을 유지한 채 값을 다르게 가질 수 있습니다. 컬럼 정보 창에서 길이를 고치면 "도메인 타입과 다름: 길이"라고 알려 주고, 배지는 `D*`가 됩니다. **도메인 타입 값으로 되돌리기**로 한 번에 맞출 수 있습니다.

컬럼 이름이 사전의 용어와 같은데 도메인 타입이 다르면, 컬럼 정보 창이 **사전 표준**을 알려 주고 **적용**을 권합니다.

![컬럼 정보 창의 도메인 타입](/guide-assets/domain-column.webp)

### 표준을 바꿀 때

도메인 타입을 고치면 그것을 쓰는 컬럼에 반영할지 묻습니다. 컬럼마다 바뀔 값을 미리 보고, 반영할 컬럼을 고릅니다. 다르게 쓰기로 한 속성은 건너뜁니다.

![도메인 타입 변경 반영 미리보기](/guide-assets/domain-propagation.webp)

- 지금 열려 있지 않은 문서는 바로 바뀌지 않습니다. 그 문서를 다음에 여는 편집자에게 "도메인 타입이 바뀌었습니다" 알림이 뜹니다.
- 반영은 되돌리기 한 번으로 취소됩니다.

### 이미 있는 문서에 논리명 채우기

데이터베이스에서 가져온 문서는 논리명이 비어 있는 경우가 많습니다. **도구 › 논리명 추론**은 사전의 단어와 용어로 `user_id`를 "회원 번호"처럼 채워 줍니다. 적용하기 전에 결과를 미리 보고 고릅니다.

## 4. 데이터베이스와 주고받기

워크스페이스의 **데이터베이스** 탭에서 연결을 등록합니다. 개발용 데이터베이스가 없으면 무료 데이터베이스를 발급받을 수 있습니다.

| 하려는 일 | 방법 |
| --- | --- |
| 데이터베이스 구조를 문서로 | 데이터베이스 탭의 **DB에서 가져오기** |
| 문서를 SQL로 | 에디터의 **SQL 생성** |
| 문서를 데이터베이스에 만들기 | SQL 생성 창의 **배포** |
| 문서를 고친 뒤 데이터베이스에 맞추기 | **마이그레이션 DDL** — 바뀐 부분만 반영하는 SQL을 만든다 |
| 데이터베이스가 바뀐 것을 문서에 가져오기 | **도구 › DB 동기화** |
| 직접 만든 문서를 데이터베이스에 연결 | **도구 › 데이터베이스 연결** |

데이터베이스에 반영하는 작업은 되돌릴 수 없습니다. 실행 전에 보여 주는 SQL을 꼭 확인하세요.

## 5. 데이터 보기

연결한 데이터베이스의 데이터를 바로 보고 고칠 수 있습니다. 데이터베이스 탭의 **데이터 보기**, 에디터의 **도구 › 데이터 보기**, 테이블 **우클릭 › 이 테이블의 데이터 보기**로 엽니다.

![데이터 브라우저](/guide-assets/data-tab.webp)

- **데이터** 탭: 머리글을 눌러 정렬하고, 조건으로 거르고, CSV로 내려받습니다.
- **행 편집**: 셀을 두 번 눌러 고칩니다. 고친 내용은 아래에 모였다가 **적용**을 눌러야 한 번에 반영됩니다. 하나라도 실패하면 전부 취소됩니다.
- **SQL** 탭: 문장을 직접 실행합니다. `Ctrl/Cmd+Enter`로 커서가 놓인 문장만 실행합니다. 데이터를 바꾸는 문장은 확인을 거칩니다.

![행 편집](/guide-assets/row-edit.webp)

데이터 보기는 편집자(Editor) 이상만 쓸 수 있습니다.

## 6. 함께 쓰기

### 멤버와 역할

워크스페이스의 **멤버** 탭에서 사람이나 팀을 초대합니다.

| 역할 | 할 수 있는 일 |
| --- | --- |
| Viewer | 보기 |
| Commenter | 보기, 댓글 |
| Editor | 문서 편집, 데이터베이스 연결, 사전과 도메인 타입 관리, 데이터 보기 |
| Owner | 위의 모든 것, 멤버 관리, 문서와 워크스페이스 삭제 |

### 같이 편집하기

같은 문서를 여러 사람이 열면 서로의 커서와 변경이 실시간으로 보입니다. 누군가 편집 창을 열어 둔 테이블은 다른 사람에게 잠긴 것으로 표시됩니다.

### 밖으로 보여 주기

- **공유**는 로그인 없이 볼 수 있는 읽기 전용 링크를 만듭니다. 기간을 정할 수 있고 언제든 거둘 수 있습니다.
- **내보내기**는 이미지와 문서 파일(`.crown`)을 만듭니다.

### 버전 기록

저장할 때마다 버전이 남습니다. **도구 › 버전 기록**에서 이전 버전을 보고, 두 버전을 비교하고, 되돌릴 수 있습니다.

## 7. 점검하기

도구 모음의 **검증**은 문서를 검사합니다. 기본 키가 없는 테이블, 타입이 맞지 않는 외래 키, 이름 규칙에 어긋난 이름, 논리명이 빠진 컬럼 등을 찾아 줍니다. 항목을 누르면 해당 테이블로 이동합니다.

## 8. 자주 묻는 것

**용어 사전과 도메인 타입은 무엇이 다른가요?**
사전은 이름의 표준이고 도메인 타입은 타입의 표준입니다. `user_email`, `backup_email`, `contact_mail`은 이름이 달라 사전 항목은 제각각이지만, 도메인 타입은 셋 다 "이메일" 하나를 씁니다.

**단어와 용어는 따로 등록하나요?**
같은 목록에 등록합니다. 도메인 타입을 고른 항목(또는 타입 표기를 적은 항목)이 용어이고, 나머지가 단어입니다.

**도메인 타입을 지우면 컬럼은 어떻게 되나요?**
컬럼의 값은 그대로입니다. 연결만 끊긴 것으로 표시됩니다.

**다른 워크스페이스로 붙여 넣으면 도메인 타입은요?**
도메인 타입은 워크스페이스에 속합니다. 다른 워크스페이스의 문서에서는 연결이 끊긴 것으로 보이고 값은 그대로입니다.

**저장은 언제 되나요?**
편집을 멈추면 자동으로 저장됩니다. `Ctrl/Cmd+S`나 **저장** 버튼으로 바로 저장할 수도 있습니다.
